# Doctrine DBAL, Doctrine ORM and Symfony on PostgreSQL

This reference covers Doctrine DBAL 4.5, Doctrine ORM 3.7, Doctrine Migrations 3.9 and Symfony 8.1 against
PostgreSQL: the connection URL, identity columns, jsonb, migrations that must run outside a transaction, and error
classes. The DBAL program ran on PHP 8.5.12, `doctrine/dbal` 4.5.0 and PostgreSQL 18.6 in October 2026.

## Symfony DATABASE_URL for PostgreSQL

Symfony's Doctrine recipe writes the PostgreSQL connection as a URL in `.env`; set `serverVersion` so Doctrine picks
the platform without opening a connection at boot.

```dotenv
DATABASE_URL="postgresql://app:!ChangeMe!@127.0.0.1:5432/app?serverVersion=18&charset=utf8"
```

The recipe ships `serverVersion=16`; change it to the major you run. Keep real credentials out of `.env` (use
`.env.local`, Symfony secrets or the environment), and add `sslmode=verify-full` for servers off the machine.

## Doctrine DBAL 4 connection parameters for pdo_pgsql

Doctrine DBAL's `pdo_pgsql` and `pgsql` drivers accept `host`, `port`, `dbname`, `user`, `password`, `charset`,
`sslmode`, `sslrootcert`, `sslcert`, `sslkey`, `sslcrl`, `gssencmode`, `persistent` (pdo_pgsql only) and
`application_name`. This program connects with them, creates a table and reads it back.

```php
use Doctrine\DBAL\DriverManager;

$conn = DriverManager::getConnection([
    'driver' => 'pdo_pgsql', 'host' => 'db.internal', 'port' => 5432, 'dbname' => 'app',
    'user' => 'app', 'password' => getenv('PGPASSWORD'), 'sslmode' => 'verify-full',
    'application_name' => 'symfony-api', 'serverVersion' => '18.6',
]);
$row = $conn->fetchAssociative('SELECT id, name FROM widgets WHERE name = ?', ['a']);
```

`serverVersion` takes the value `SHOW server_version` prints. Without it, DBAL connects at first use to detect the
platform.

## Doctrine DBAL 4 identity columns and jsonb

DBAL 4 creates `autoincrement` columns on PostgreSQL as `GENERATED BY DEFAULT AS IDENTITY`, not `SERIAL`. A JSON
column becomes `jsonb` with the `jsonb` platform option. This schema code produced the DDL below on 18.6.

```php
use Doctrine\DBAL\Schema\Table;
use Doctrine\DBAL\Types\Types;

$t = new Table('widgets');
$t->addColumn('id', Types::BIGINT, ['autoincrement' => true]);
$t->addColumn('name', Types::STRING, ['length' => 100]);
$t->addColumn('attrs', Types::JSON, ['platformOptions' => ['jsonb' => true]]);
$t->setPrimaryKey(['id']);
$t->addUniqueIndex(['name']);
// CREATE TABLE widgets (id BIGINT GENERATED BY DEFAULT AS IDENTITY NOT NULL, name VARCHAR(100) NOT NULL,
//                       attrs JSONB NOT NULL, PRIMARY KEY (id))
```

Databases created under DBAL 3 keep their `SERIAL` columns; the DBAL guide "PostgreSQL identity migration" converts
them. Reading a `jsonb` column through `fetchAssociative` returns a string; the `Types::JSON` type decodes it when
you convert values or use the ORM.

## Doctrine DBAL transactions and error classes

`Connection::transactional()` commits when the closure returns and rolls back when it throws. DBAL maps SQLSTATEs to
exception classes, so catch the class, not the message.

```php
use Doctrine\DBAL\Exception\DeadlockException;
use Doctrine\DBAL\Exception\UniqueConstraintViolationException;

try {
    $conn->transactional(function ($c) {
        $c->insert('widgets', ['name' => 'a', 'attrs' => ['x' => 1]], ['attrs' => Types::JSON]);
    });
} catch (UniqueConstraintViolationException $e) {     // 23505; $e->getSQLState()
    // conflict
} catch (DeadlockException $e) {                       // 40P01 and 40001: retry the whole transaction
    // retry with backoff
}
```

## Doctrine Migrations outside a transaction

Doctrine Migrations wraps each migration in a transaction by default. Override `isTransactional()` to return `false`
for a migration that runs `CREATE INDEX CONCURRENTLY`, which PostgreSQL refuses inside a transaction block. This
class follows the Doctrine Migrations 3.9 reference; it was not run for this page.

```php
final class Version20261028000000 extends AbstractMigration
{
    public function isTransactional(): bool
    {
        return false;
    }

    public function up(Schema $schema): void
    {
        $this->addSql('CREATE INDEX CONCURRENTLY IF NOT EXISTS orders_created_at_idx ON orders (created_at)');
    }
}
```

## Doctrine ORM notes for PostgreSQL

Doctrine ORM 3.7 sits on DBAL 4, so the connection, identity and error rules above apply. Map `timestamptz` columns
with the `datetimetz_immutable` type and keep the PHP default timezone and the session `TimeZone` both UTC. Use
`#[ORM\Version]` for optimistic locking, and `$em->find(Order::class, $id, LockMode::PESSIMISTIC_WRITE)` inside a
transaction for `SELECT ... FOR UPDATE`. For bulk loads, skip the ORM: use DBAL with `Pdo\Pgsql::copyFromArray()` on
the native connection.
